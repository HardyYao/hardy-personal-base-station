今天上午去医院复查，下午一回去上班就忙得飞起，发现了两个不小的系统问题。

一个是涉及某个位置的价格计算有问题，还好我们公司暂时用不到那个数值，所以不算特别严重，而且我也很容易就修正了。

另一个是发现单据关联异常，我看到那个问题的时候人都傻了，我们总监在说问题的时候，我就在那里思考：问题到底出在哪里？我怎么可能会犯这种低级错误？

后面排查了很久，发现是因为我有个接口在抛转数据时，用到了那个 Java 开发小伙子两张数据表的数据，然后他那张表里面有十来笔异常数据，就导致我转单时出现异常。

然后我跟他说，这个事情不用讲，意思是我来承担这个事情就好了。

但是，后面他发现，那里出现的几笔异常单号数据，是因为我上个月有一次修复一个 bug 时，改了他的单号生成机制，然后造成了一个偶现的 bug。

这个问题我们当时发现了，也修复了，然后我以为他把关联的异常数据也都处理好了，但他说他以为那些单号没问题，就没管了，没想到造成我这边的严重 bug。

所以这个事情，起因还是因为我当时着急修复一个 bug，没考虑清楚造成的。

然后那个 Java 开发小伙子的善后工作也没做好吧，如果是我的话，肯定会把那些异常数据给修复的，因为数据量也不多，而我是有点数据洁癖的，受不了那些异常数据挂在那里，但他觉得无所谓。

不过我觉得还好我扛住了压力，从一开始就打算自己来担这个责，也就不用被打脸了。

下午接连发现线上环境的两个问题，尤其是这第二个，我们总监当时生气了，不过我保持了冷静，看到他有情绪，我就不说话，专心思考怎么解决问题。

中间一度以为是那个 Java 开发小伙子造成的问题，我也没有责怪他。

后面我们总监出去办完事回来的时候，气也消了一大半了，我也找到了问题原因，就说只是某个时间段的一些数据受到影响，在那之前和之后的数据都不受影响。

我跟他说受影响的总共有八笔数据，然后有两笔我修正了，另外六笔得他来处理，相关信息我也都整理好发给他了，最后问题也算圆满解决了。

好巧不巧，下午其他同事也接连找我处理一些问题，一个个都还很着急。

好在我全程保持了冷静，但凡当时情绪上来点，在那种高压环境下，我都有可能跟人吵架。
